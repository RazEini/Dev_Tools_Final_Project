# פרויקט מסכם – הקמת אתר Drupal באמצעות Docker

## א. מי אנחנו

**צוות הפרויקט:**
- רז עייני
- אריאל לוין
- רז יעקבי

מוגש כפרויקט מסכם בקורס **כלי פיתוח**, סמסטר ב' תשפ"ו.

---

## ב. מה נדרשנו לעשות

להקים אתר תוכן מבוסס **Drupal** יחד עם בסיס נתונים (**MySQL**), כאשר שני חלקי המערכת רצים בתוך **Docker containers** נפרדים המחוברים לרשת משותפת.

בנוסף נדרשנו:

- להגדיר משתמש מנהל (`demoadmin`) ומשתמשים עבור כל אחד מחברי הצוות.
- לבנות מנגנון **גיבוי ושחזור** לבסיס הנתונים ולקבצי ה-Drupal (volumes), כך שניתן יהיה לשחזר את האתר במלואו – כולל כל המשתמשים והתכנים – על מכונה אחרת.
- לכתוב את כל התהליך כסקריפטים אוטומטיים: `setup.sh`, `backup.sh`, `restore.sh`, `cleanup.sh`.
- לשמור ולסנכרן את כל התוצרים (סקריפטים + קבצי גיבוי) בריפוזיטורי Git משותף באופן אוטומטי.

---

## ג. מה עשינו

1. **הקמת תשתית הרשת**  
   הקמנו רשת Docker פנימית בשם `drupal-net`.  
   הרשת מאפשרת תקשורת מאובטחת בין קונטיינר בסיס הנתונים לקונטיינר האפליקציה.

2. **הגדרת בסיס הנתונים**  
   הרצנו קונטיינר MySQL בגרסה 8.0 בשם `drupal-db`.  
   הוגדרו משתמש, סיסמה ובסיס נתונים ייעודיים, ופורט ברירת המחדל 3306 נחשף.

3. **הגדרת אפליקציית Drupal**  
   הרצנו קונטיינר `drupal:latest` בשם `drupal-web` על פורט 8080.  
   הוגדרו 4 volumes נפרדים: `modules`, `profiles`, `themes` ו-`sites` —  
   כדי להבטיח הפרדה מלאה ושמירה על התוכן והתוספים גם בעת מחיקה או שחזור.

4. **אוטומציית ההתקנה**  
   התקנת ה-CMS בוצעה באופן אוטומטי באמצעות הפקודה `drush site-install`.  
   הוגדרו שם האתר, השפה, ומשתמש המנהל הראשוני: `demoadmin` / `secretpass`.

5. **ניהול משתמשים**  
   יצרנו משתמש נוסף עבור כל אחד מחברי הצוות דרך ממשק הניהול של Drupal.

6. **כתיבת סקריפטי אוטומציה וסנכרון Git**  
   פיתחנו ארבעה סקריפטים ב-Bash לניהול מלא של מחזור החיים של המערכת, הכוללים אינטגרציה מלאה מול GitHub:

   | סקריפט | תפקיד |
   |--------|--------|
   | `setup.sh` | מקים את התשתית מאפס (רשת, קונטיינרים והתקנת Drupal) |
   | `backup.sh` | מגבה את ה-DB וה-volumes, ומבצע **אוטומטית** `git commit` ו-`git push` ל-GitHub |
   | `restore.sh` | מוריד **אוטומטית** את הגיבוי העדכני מ-GitHub (`git pull`) ומטעין את ה-DB וה-volumes למערכת |
   | `cleanup.sh` | מוחק את הקונטיינרים, ה-volumes, הרשת וה-images ומחזיר את הסביבה למצב נקי |

7. **סנכרון גרסאות**  
   העלינו את כל הסקריפטים וקובצי הגיבוי לריפוזיטורי Git המשותף.

## ד. באילו טכנולוגיות השתמשנו

| טכנולוגיה          | תפקיד                                                     |
|--------------------|-----------------------------------------------------------|
| Docker             | הרצת כל חלקי המערכת בקונטיינרים מבודדים                    |
| Docker Network     | תקשורת פנימית בין קונטיינר Drupal לקונטיינר MySQL         |
| Docker Volumes     | שמירת קבצי Drupal (modules / profiles / themes / sites)    |
| MySQL 8.0          | בסיס הנתונים של האתר                                       |
| Drupal (latest)    | מערכת ניהול התוכן (CMS) של האתר                            |
| Drush              | כלי שורת פקודה להתקנת וניהול Drupal ללא אשף התקנה ידני    |
| Bash               | כתיבת סקריפטי האוטומציה (setup / backup / restore / cleanup) |
| Git & GitHub       | סנכרון ושמירת קוד וקובצי גיבוי בענן בין סשנים ומכונות      |

## ה. מדריך Step-By-Step למשתמש

### 1. שכפול הריפוזיטורי

```bash
git clone <your-repository-address>
cd <project-folder>
```

### 2. הגדרת הרשאות וזהות Git (חד-פעמי למכונה)

הענקת הרשאות הרצה לסקריפטים:
```bash
chmod +x setup.sh backup.sh restore.sh cleanup.sh
```

*(במידה ועובדים בסביבת Windows/WSL ונתקלים בשגיאת `bad interpreter`, מריצים: `sed -i 's/\r$//' *.sh`)*

**חשוב:** כדי שהגיבוי האוטומטי ל-GitHub יעבוד ללא שגיאות במכונה חדשה, יש לוודא שהוגדרה זהות Git:
```bash
git config --global user.email "your_email@example.com"
git config --global user.name "Your Name"
```

---

### 3א. אם זו הפעלה ראשונה (אין עדיין גיבוי בריפוזיטורי)

```bash
./setup.sh
```

הסקריפט מקים לבד: רשת Docker, קונטיינר MySQL, קונטיינר Drupal, ומתקין את האתר אוטומטית עם משתמש מנהל `demoadmin` / `secretpass`.

---

### 3ב. אם קיים גיבוי בריפוזיטורי (למשל במכונה חדשה או אצל חבר צוות)

```bash
./restore.sh
```

הסקריפט יבצע **אוטומטית** `git pull` כדי למשוך את הגיבוי הכי עדכני מ-GitHub, יאתר אותו בתיקיית `backups/`, וישחזר אותו למערכת במלואו.  
לחלופין, ניתן להעביר נתיב לגיבוי ספציפי: `./restore.sh backups/backup_<TIMESTAMP>`

**במידה ורוצים לבצע שחזור ידני של MySQL בלבד (לפי דרישות חלק 5 במטלה):**

```bash
# 1. יצירת בסיס הנתונים במידה ואינו קיים
docker exec drupal-db sh -c "exec mysqladmin -uroot -pmy-secret-pw create drupal"

# 2. פרישת הגיבוי הדחוס והזרקתו לבסיס הנתונים
gunzip < backups/backup_<TIMESTAMP>/drupal_db_backup.sql.gz | docker exec -i drupal-db sh -c "exec mysql -h 127.0.0.1 -uroot -pmy-secret-pw --force drupal"

# 3. הפעלה מחדש של קונטיינר Drupal להחלת השינויים
docker restart drupal-web
```

---

### 4. כניסה לאתר

פותחים דפדפן בכתובת:

```
http://localhost:8080
```

לוחצים על **"כניסה"** ומתחברים עם אחד המשתמשים הקיימים (למשל `demoadmin` / `secretpass`, או המשתמש האישי שהוגדר לכם).

---

### 5. עבודה שוטפת על האתר

ניתן להוסיף תכנים, לערוך עיצוב וליצור משתמשים נוספים דרך מסך הניהול (התפריט העליון לאחר ההתחברות).

---

### 6. גיבוי וסנכרון אוטומטי ל-GitHub בסיום העבודה

```bash
./backup.sh
```

הסקריפט יוצר גיבוי מלא בתיקיית `backups/` ומיד מבצע **`git add`**, **`git commit`** ו-**`git push`** אוטומטית ל-GitHub. אין צורך להריץ פקודות Git ידניות.

**במידה ורוצים לבצע גיבוי ידני של MySQL בלבד (לפי דרישות חלק 4 במטלה):**

```bash
sudo apt update
sudo apt install mysql-client-core-8.0
docker exec drupal-db sh -c "exec mysqldump --all-databases -uroot -pmy-secret-pw" | gzip > backups/my-drupal.backup.sql.gz
git add backups/
git commit -m "manual backup <date>"
git push
```

---

### 7. ניקוי הסביבה בסיום העבודה

```bash
./cleanup.sh
```

מוחק את כל הקונטיינרים, ה-volumes, הרשת וה-images שנוצרו עבור הפרויקט, ומחזיר את מכונת ה-Linux למצב נקי. הסקריפט מבקש אישור לפני המחיקה.

---

## ו. מידע נוסף

- **חשוב מאוד:** יש להריץ `backup.sh` **לפני** `cleanup.sh` – אחרת השינויים שביצעתם לא יעלו ל-GitHub ויימחקו מהמכונה.
- **סנכרון בין מכונות:** הודות לאינטגרציית ה-Git בסקריפטים, מעבר בין מכונות וירטואליות מתבצע ב-2 פקודות בלבד במכונה החדשה: `git clone <URL>` ואז `./restore.sh`.
- פרטי חיבור לבסיס הנתונים (סיסמת root, שם משתמש/סיסמה) מוגדרים כמשתנים בראש כל אחד מהסקריפטים. אם משנים אותם, יש לעדכן בכל הארבעה יחד כדי לשמור על עקביות.
- אם קונטיינר ה-DB עדיין "מתעורר" בזמן הרצת `setup.sh` או `restore.sh`, הסקריפטים ממתינים אוטומטית (`mysqladmin ping`) עד שהוא מוכן – אין צורך בהתערבות ידנית.
