---

## ב. מה נדרשנו לעשות

להקים אתר תוכן מבוסס **Drupal** יחד עם בסיס נתונים (**MySQL**), כאשר שני חלקי המערכת רצים בתוך **Docker containers** נפרדים המחוברים לרשת משותפת. בנוסף נדרשנו:

- להגדיר משתמש מנהל (`demoadmin`) ומשתמשים עבור כל אחד מחברי הצוות.
- לבנות מנגנון **גיבוי ושחזור** לבסיס הנתונים ולקבצי ה-Drupal (volumes), כך שניתן יהיה לשחזר את האתר במלואו - כולל כל המשתמשים - על מכונה אחרת.
- לכתוב את כל התהליך כסקריפטים אוטומטיים: `setup.sh`, `backup.sh`, `restore.sh`, `cleanup.sh`.
- לשמור את כל התוצרים (סקריפטים + קבצי גיבוי) בריפוזיטורי Git משותף.

---

## ג. מה עשינו

1. הקמנו רשת Docker פנימית (`drupal-net`) המחברת בין קונטיינר בסיס הנתונים לקונטיינר Drupal.
2. הרצנו קונטיינר `mysql:8.0` (`drupal-db`) עם משתמש, סיסמה ובסיס נתונים ייעודיים, וחשפנו את פורט ברירת המחדל (3306).
3. הרצנו קונטיינר `drupal:latest` (`drupal-web`) עם 4 volumes נפרדים (`modules`, `profiles`, `themes`, `sites`) כדי שנוכל לגבות ולשחזר תוכן בלי להתקין הכל מחדש, וחשפנו אותו על פורט 8080 (מופנה לפורט 80 בקונטיינר).
4. הפעלנו את תהליך התקנת Drupal באופן אוטומטי (`drush site-install`) - כולל שם האתר, שפה, ומשתמש המנהל `demoadmin` / `secretpass`.
5. יצרנו משתמש נוסף עבור כל אחד מחברי הצוות דרך מסך הניהול של Drupal.
6. כתבנו ארבעה סקריפטים המבצעים את כל התהליך אוטומטית:
   - **setup.sh** - מקים את כל התשתית מאפס (רשת + שני קונטיינרים + התקנת Drupal).
   - **backup.sh** - מגבה את בסיס הנתונים (`mysqldump --all-databases`) ואת כל ה-volumes לתיקיית `backups/` עם חותמת זמן.
   - **restore.sh** - משחזר גיבוי קיים (DB + volumes) על כל מכונה, כולל כל המשתמשים שנוצרו במקור.
   - **cleanup.sh** - מוחק את כל הקונטיינרים, ה-volumes, הרשת וה-images שנוצרו, ומחזיר את הסביבה למצב נקי.
7. העלינו את כל הסקריפטים וקובצי הגיבוי לריפוזיטורי Git המשותף.

---

## ד. באילו טכנולוגיות השתמשנו

| טכנולוגיה | תפקיד |
|---|---|
| Docker | הרצת כל חלקי המערכת בקונטיינרים מבודדים |
| Docker Network | תקשורת פנימית בין קונטיינר Drupal לקונטיינר MySQL |
| Docker Volumes | שמירת קבצי Drupal (modules/profiles/themes/sites) בין הפעלות |
| MySQL 8.0 | בסיס הנתונים של האתר |
| Drupal (latest) | מערכת ניהול התוכן (CMS) של האתר |
| Drush | כלי שורת פקודה להתקנת/ניהול Drupal ללא צורך באשף התקנה ידני |
| Bash | כתיבת סקריפטי האוטומציה (setup / backup / restore / cleanup) |
| Git | שמירת קוד וקבצי גיבוי בריפוזיטורי משותף |

## ה. מדריך Step-By-Step למשתמש פשוט

### 1. שכפול הריפוזיטורי
```bash
git clone <your-repository-address>
cd <project-folder>
```

### 2. הענקת הרשאות הרצה לסקריפטים (פעם אחת)
```bash
chmod +x setup.sh backup.sh restore.sh cleanup.sh
```

### 3א. אם זו הפעלה ראשונה (אין עדיין גיבוי)
```bash
./setup.sh
```
הסקריפט יקים לבד: רשת Docker, קונטיינר MySQL, קונטיינר Drupal, ויתקין את האתר אוטומטית עם משתמש מנהל `demoadmin` / `secretpass`.

### 3ב. אם קיים גיבוי (למשל אחרי clone אצל חבר צוות)
```bash
./restore.sh backups/backup_<TIMESTAMP>
```
אם לא מציינים תיקיית גיבוי ספציפית, הסקריפט ישתמש אוטומטית בגיבוי העדכני ביותר בתיקיית `backups/`.

### 4. כניסה לאתר
פותחים דפדפן בכתובת:
```
http://localhost:8080
```
לוחצים על **"כניסה"** ומתחברים עם אחד המשתמשים הקיימים (למשל `demoadmin` / `secretpass`, או המשתמש האישי שהוגדר לכם).

### 5. עבודה שוטפת על האתר
ניתן להוסיף תכנים, לערוך עיצוב, וליצור משתמשים נוספים דרך מסך הניהול (התפריט העליון לאחר ההתחברות).

### 6. גיבוי לפני סיום עבודה
```bash
./backup.sh
```
נוצרת תיקייה חדשה בתוך `backups/` עם קובץ dump של בסיס הנתונים וכל קבצי ה-volumes. יש להעלות אותה ל-Git:
```bash
git add backups/
git commit -m "backup <date>"
git push
```

### 7. ניקוי הסביבה בסיום העבודה
```bash
./cleanup.sh
```
מוחק את כל הקונטיינרים, ה-volumes, הרשת וה-images שנוצרו עבור הפרויקט, ומחזיר את מכונת ה-Linux למצב שהייתה בו לפני ההתקנה. הסקריפט מבקש אישור לפני המחיקה.

---

## ו. מידע נוסף

- **חשוב:** יש להריץ `backup.sh` **לפני** `cleanup.sh` - אחרת כל התוכן והמשתמשים שנוצרו יימחקו לצמיתות.
- פרטי חיבור לבסיס הנתונים (סיסמת root, שם משתמש/סיסמה) מוגדרים כמשתנים בראש כל אחד מהסקריפטים - אם משנים אותם, יש לעדכן בכל הארבעה יחד כדי לשמור על עקביות.
- אם קונטיינר ה-DB עדיין "מתעורר" בזמן הרצת `setup.sh` או `restore.sh`, הסקריפטים ממתינים אוטומטית (`mysqladmin ping`) עד שהוא מוכן - אין צורך בהתערבות ידנית.
- כתובת `http://localhost:8080` תקפה כל עוד עובדים על אותה מכונת Linux. אם עוברים למכונה וירטואלית אחרת (כמו במכונות אפקה), יש לבצע שוב `git clone` + `restore.sh` על המכונה החדשה.
